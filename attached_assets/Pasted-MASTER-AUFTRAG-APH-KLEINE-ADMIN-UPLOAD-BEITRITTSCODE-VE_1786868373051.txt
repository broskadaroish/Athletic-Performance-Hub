TEIL B – PROFILFOTO / VEREINSLOGO UPLOAD
============================================================

max. 10 MB

Sehr kleine Bilder funktionieren.

Das betrifft:
- Profilfoto
- Vereinslogo

ZIEL:
Die tatsächliche Upload-Kette prüfen und Ursache beheben.

============================================================
B1. ZUERST URSACHE PRÜFEN
============================================================

Prüfe:

- st.file_uploader
- maxUploadSize
- .streamlit/config.toml
- eigene Python-Dateigrößenprüfung
- PIL/Image-Verarbeitung
- Bildformatprüfung
- Speicherung als BLOB
- DB-Feld
- Nginx client_max_body_size
- Docker/Proxy
- Streamlit-Limits

WICHTIG:
Nicht einfach nur den Text „10 MB“ ändern.

Feststellen, wo die echte Grenze liegt.

============================================================
B2. GEWÜNSCHTES VERHALTEN
============================================================

Dateien bis 10 MB sollen grundsätzlich akzeptiert werden,
wenn sie ein unterstütztes Bildformat besitzen.

Unterstützte Formate:
bestehende Formate beibehalten, z.B.
- JPG/JPEG
- PNG
- ggf. WEBP, falls bisher unterstützt

Wenn ein großes Handyfoto geladen wird:

Bild nach dem Upload sinnvoll optimieren.

Empfehlung:
- EXIF-Ausrichtung berücksichtigen
- Maximalabmessung sinnvoll begrenzen, z.B. ca. 1600–2000 px längste Kante
- JPEG/PNG sinnvoll komprimieren
- Profilfoto/Logo nicht unnötig in Originalauflösung speichern

WICHTIG:
Keine sichtbare schlechte Qualität erzeugen.

Ziel:
schnellere Ladezeiten + kleinere DB-/Speicherlast.

============================================================
B3. PROFILFOTO UND LOGO GETRENNT PRÜFEN
============================================================

Profilfoto:
- Upload bis 10 MB
- Vorschau
- Speichern
- Reload
- Bild weiterhin sichtbar

Vereinslogo:
- Upload bis 10 MB
- Vorschau
- Speichern
- Reload
- Logo weiterhin sichtbar

Bestehende Benutzer-/Vereinszuordnung nicht verändern.

============================================================
B4. FEHLERMELDUNGEN
============================================================

Bei zu großer Datei:
klare Meldung:

„Die Datei ist größer als 10 MB.“

Bei ungültigem Bild:
„Das Bild konnte nicht verarbeitet werden.“

Keine technischen Stacktraces im UI.

TEIL C – TRAINER-BEITRITTSCODE
============================================================

AKTUELLER BESTAND:

Es existieren:

registrier_code_laden(verein_id)
registrier_code_regenerieren(verein_id)

Der Vereinsadmin/Superadmin sieht unter Einstellungen:

„Trainer-Beitrittscode“

und kann einen neuen Code generieren.

Problem:
Nach aktuellem Bestand ist nicht ersichtlich, dass dieser Code in der
Trainerregistrierung tatsächlich abgefragt und validiert wird.

ZIEL:
Den vorhandenen Trainer-Beitrittscode funktional mit der
Trainerregistrierung verbinden.

============================================================
C1. TRAINERREGISTRIERUNG BESTAND PRÜFEN
============================================================

Prüfe zuerst exakt:

- Trainer-Registrierung
- wie aktuell technischer Mandant / Trainerkonto erstellt wird
- wann verein_id gesetzt wird
- wie Rolle gespeichert wird
- wie Freischaltung funktioniert
- wie Lizenz/Trial bei selbständigem Trainer funktioniert

WICHTIG:
Bestehende normale Trainerregistrierung NICHT kaputtmachen.

Es muss zwischen zwei Fällen unterschieden werden können:

A) selbständiger Trainer / eigener Trainerkunde
B) Trainer tritt einem bestehenden Verein bei

============================================================
C2. TRAINERREGISTRIERUNG – AUSWAHL ERGÄNZEN
============================================================

Im Tab „Trainer registrieren“ eine klare Auswahl:

Wie möchtest du APH nutzen?

Option A:
„Als eigener Trainer registrieren“

→ bestehender Ablauf bleibt unverändert.

Option B:
„Einem Verein beitreten“

→ zusätzlich Feld:

Trainer-Beitrittscode

Hinweis:
„Den Beitrittscode erhältst du von deinem Verein.“

============================================================
C3. CODE VALIDIEREN
============================================================

Bei „Einem Verein beitreten“:

Code normalisieren:
- trim
- case-insensitiv bzw. passend zur aktuellen Großschreibung

Dann prüfen:

SELECT id, name, aktiv, gesperrt ...
FROM vereine
WHERE registrier_code = ?

Nur gültigen, aktiven Verein akzeptieren.

Wenn Code ungültig:
„Der Beitrittscode ist ungültig.“

Wenn Verein deaktiviert/gesperrt:
keine Registrierung zu diesem Verein ermöglichen.

Keine Informationen über andere Vereine unnötig preisgeben.

============================================================
C4. TRAINER DEM VEREIN ZUORDNEN
============================================================

Bei gültigem Code:

Trainerkonto erstellen mit:

- verein_id = gefundener Verein
- rolle = Trainer
- normale Personendaten
- E-Mail/Benutzername
- Passwort-Hash
- Zustimmung AGB/Datenschutz wie bisher

WICHTIG:
Keinen neuen technischen Mandanten für diesen Trainer erzeugen.

Der Trainer gehört direkt zum bestehenden Verein.

============================================================
C5. FREISCHALTUNG
============================================================

Bestehende Freischaltungslogik verwenden.

Aktueller UI-Text sagt:

„Nach der Registrierung musst du das Konto unter Benutzerverwaltung freischalten.“

Daher:

Trainer nach Beitritt zunächst so anlegen, dass der Vereinsadmin ihn in
Benutzerverwaltung prüfen/freischalten kann.

Keine automatische Freischaltung, wenn das bisherige System das nicht vorsieht.

============================================================
C6. LIZENZLOGIK BEI VEREINSTRAINER
============================================================

Ganz wichtig:

Trainer, der einem Verein per Beitrittscode beitritt,
bekommt KEIN eigenes kostenpflichtiges Trainer-Abo.

Er nutzt die Vereinslizenz im Rahmen:
- max_trainer
- max_spieler
- bestehender Vereinslimits

Prüfen:
Vor Registrierung ggf. max_trainer-Limit des Vereins berücksichtigen.

Wenn Limit erreicht:
klare Meldung:
„Das Trainerlimit des Vereins ist erreicht.“

Keine Stripe-Session für diesen Beitrittsfall erzeugen.

============================================================
C7. BESTEHENDER „EIGENER TRAINER“-FLOW
============================================================

Der normale Trainer-Kundenflow bleibt unverändert:

- eigener technischer Mandant
- eigenes Trainer-Abo
- Stripe
- Trial
- Vertrag
- Kundennummer

Nur die neue Option „Einem Verein beitreten“ nutzt den Beitrittscode.

============================================================
C8. CODE NEU GENERIEREN
============================================================

Bestehendes Verhalten beibehalten:

„Neu generieren“
→ neuer Code ersetzt alten.

Erwartung:

- alter Code funktioniert für neue Trainer nicht mehr
- neuer Code funktioniert
- bereits zugeordnete Trainer bleiben beim Verein
- keine bestehenden Benutzer werden verändert

============================================================
C9. SICHERHEIT
============================================================

Prüfen:

- eindeutiger Code
- ausreichend zufällig
- keine SQL-Injection
- kein Vereinswechsel bestehender Accounts durch fremden Code
- bestehende E-Mail-Duplikatprüfung bleibt erhalten
- bestehende Benutzername-Duplikatprüfung bleibt erhalten
- AGB/Datenschutz bleiben Pflicht
