WICHTIG:
Noch NICHT deployen.

Bestehende Tests und Trainingsdaten vollständig erhalten.

============================================================
1. PRODUKTIONSFEHLER
============================================================

Aktueller Fehler auf der Mannschafts-/Dashboard-Seite:

ValueError:
time data '18.08.2026' does not match format '%Y-%m-%d'

Trace u. a.:

app.py
page_dashboard()
Filter:
„Spieler ohne Test > 30 Tage“

Die Filterlogik verwendet aktuell sinngemäß:

datetime.strptime(x["datum"], "%Y-%m-%d")

Mindestens ein gespeicherter Test hat aber:

18.08.2026

statt:

2026-08-18

Dadurch crasht die komplette Mannschaftsseite.

============================================================
2. ZIEL
============================================================

Datumswerte müssen robust verarbeitet werden.

Folgende Formate mindestens akzeptieren:

YYYY-MM-DD
z. B.
2026-08-18

DD.MM.YYYY
z. B.
18.08.2026

Optional vorhandene Zeit-/Suffixformate ebenfalls berücksichtigen,
wenn sie im bestehenden APH bereits vorkommen.

Ein ungültiger oder leerer Datumswert darf NICHT die gesamte Seite crashen.

============================================================
3. KEIN EINZELNER INLINE-FIX
============================================================

NICHT nur diese eine strptime-Zeile mit try/except versehen.

Prüfe, ob APH bereits eine zentrale Datumsparser-Funktion besitzt.

Insbesondere vorhandene Funktionen wie:

alter_am_datum()
bestehende Datumshilfen in database.py / app.py

prüfen und möglichst wiederverwenden.

Falls keine passende allgemeine Funktion existiert:

eine kleine zentrale Helper-Funktion erstellen, z. B.:

parse_datum_safe(value) -> date | None

Sie soll:

- datetime/date direkt akzeptieren
- YYYY-MM-DD akzeptieren
- DD.MM.YYYY akzeptieren
- ggf. vorhandene Uhrzeitsuffixe sauber behandeln
- bei leer/None/ungültig → None
- niemals ValueError bis in die UI durchreichen

Keine dritte oder vierte unabhängige Datumslogik bauen.

============================================================
4. MANNSCHAFTSFILTER REPARIEREN
============================================================

Den Filter:

„Spieler ohne Test > 30 Tage“

auf den sicheren Parser umstellen.

Für jeden Testdatensatz:

- Datum erfolgreich geparst
  → Alter des Tests berechnen

- Datum leer/ungültig
  → diesen Eintrag nicht zum Crash führen lassen

Fachlich sinnvoll behandeln:

Wenn für einen Test kein gültiges Datum existiert,
darf daraus kein falscher „frischer Test“ entstehen.

Dokumentiere, wie dieser Sonderfall behandelt wird.

10. FILTERLOGIK
============================================================

Pflichtfälle:

Heute beispielhaft:
18.08.2026

letzter Test:
2026-08-10
→ nicht >30 Tage

letzter Test:
10.08.2026
→ gleiches Ergebnis

letzter Test:
2026-06-01
→ >30 Tage

letzter Test:
01.06.2026
→ gleiches Ergebnis

leeres Datum
→ kein Crash

ungültiges Datum:
"abc"
→ kein Crash

None
→ kein Crash

============================================================
11. MEHRERE TESTS PRO SPIELER
============================================================

Wenn mehrere Tests derselben Art existieren:

immer den tatsächlich neuesten gültigen Test verwenden.

Nicht lexikografisch Strings vergleichen,
sondern echte date/datetime-Werte.

Beispiel:

"31.12.2025"
und
"2026-01-02"

→ 02.01.2026 ist neuer.
