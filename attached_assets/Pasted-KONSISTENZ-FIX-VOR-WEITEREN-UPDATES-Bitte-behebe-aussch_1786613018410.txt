1. docker-compose.yml IM REPOSITORY AKTUALISIEREN
==================================================

Der produktive Server wurde manuell bereits so ergänzt, dass folgende Variablen aus .env an den Docker-Container weitergegeben werden:

APP_BASE_URL
SMTP_HOST
SMTP_PORT
SMTP_USERNAME
SMTP_PASSWORD
SMTP_FROM
SUPPORT_EMAIL
SESSION_SECRET
SECRET_KEY

Diese Struktur muss auch im Repository in docker-compose.yml enthalten sein, damit zukünftige Deployments die funktionierende Produktionskonfiguration nicht wieder entfernen.

Unter environment: soll vorhanden sein:

APP_BASE_URL:      ${APP_BASE_URL}
SMTP_HOST:         ${SMTP_HOST}
SMTP_PORT:         ${SMTP_PORT}
SMTP_USERNAME:     ${SMTP_USERNAME}
SMTP_PASSWORD:     ${SMTP_PASSWORD}
SMTP_FROM:         ${SMTP_FROM}
SUPPORT_EMAIL:     ${SUPPORT_EMAIL}
SESSION_SECRET:    ${SESSION_SECRET}
SECRET_KEY:        ${SECRET_KEY}

WICHTIG:
Nur Variablennamen committen.
Keine echten Werte oder Passwörter.

.env bleibt in:
.gitignore
.dockerignore

2. start.sh PORT KONSISTENT MACHEN
==================================================

Aktuell:

exec streamlit run app.py --server.port 8082

ändern auf:

exec streamlit run app.py --server.port "${PORT:-8082}"

Damit gilt:

- wenn PORT gesetzt ist → PORT verwenden
- wenn PORT fehlt → 8082 als sicherer Fallback

WICHTIG:
Nicht auf 8080 erzwingen, solange der produktive Compose-Port 8082:8082 verwendet wird.

Die aktuell funktionierende Produktionskonfiguration darf nicht beschädigt werden.
