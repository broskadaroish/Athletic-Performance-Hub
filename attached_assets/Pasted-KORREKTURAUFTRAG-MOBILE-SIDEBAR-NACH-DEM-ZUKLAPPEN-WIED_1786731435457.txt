KORREKTURAUFTRAG – MOBILE SIDEBAR NACH DEM ZUKLAPPEN WIEDER ÖFFNEN

Aktueller Stand:

Die neue Mobile-Sidebar funktioniert grundsätzlich.

Auf Android Chrome / Handy-Browser unter aphsystem.de:
- Sidebar kann geöffnet werden.
- Desktop-Navigation wird korrekt angezeigt.
- Der Pfeil zum Zuklappen ist sichtbar.
- Nach dem Zuklappen verschwindet jedoch der Öffnen-Button/Pfeil vollständig.
- Danach kann der Benutzer die Sidebar nicht mehr öffnen.

Das muss korrigiert werden.

WICHTIG:
Die bestehende Navigation, Rollenlogik, Session-Logik und Desktop-Version NICHT umbauen.

--------------------------------------------------
1. ZIEL
--------------------------------------------------

Auf Smartphone-Browsern ≤ 768px muss IMMER eine Möglichkeit vorhanden sein,
die Sidebar wieder zu öffnen.

Gewünschtes Verhalten:

SIDEBAR GESCHLOSSEN:
→ kleiner Öffnen-Button oben links sichtbar
→ z.B. "☰" oder "»"
→ mindestens 44x44 px Touch-Fläche
→ gut sichtbar auf dem dunklen APH-Hintergrund
→ position: fixed
→ hoher z-index
→ darf nicht zusammen mit der Sidebar verschwinden

SIDEBAR GEÖFFNET:
→ bestehende vollständige Desktop-Sidebar anzeigen
→ der vorhandene Streamlit-Pfeil darf zum Schließen verwendet werden
→ Navigation und Rollenrechte unverändert

Nach dem Schließen:
→ externer APH-Öffnen-Button muss weiterhin sichtbar bzw. wieder sichtbar sein.

--------------------------------------------------
2. WICHTIGER ARCHITEKTURPUNKT
--------------------------------------------------

Der eigene APH-Button darf NICHT innerhalb von

[data-testid="stSidebar"]

liegen.

Sonst verschwindet er beim Schließen der Sidebar ebenfalls.

Der Button muss außerhalb der Sidebar direkt in den Parent-DOM der Streamlit-Seite
injiziert werden.

Der bereits vorhandene Ansatz mit:

components.html()
window.parent.document

soll dafür verwendet bzw. korrigiert werden.

--------------------------------------------------
3. BESTEHENDEN HOTFIX PRÜFEN
--------------------------------------------------

Prüfe zuerst die aktuelle Implementierung von:

inject_mobile_sidebar_opener()

in mobile.py.

Prüfe insbesondere:

- Wo #aph-menu-btn tatsächlich in den DOM eingefügt wird.
- Ob der Button versehentlich innerhalb der Sidebar landet.
- Ob Streamlit bei einem rerun den Button entfernt.
- Ob CSS den Button im geschlossenen Zustand versteckt.
- Ob JavaScript den Button nach dem ersten Öffnen entfernt.
- Ob der Button nach Sidebar-Collapse noch im parent.document vorhanden ist.
- Ob ein Streamlit-Rerun den Button verliert.

NICHT einfach weitere CSS-Selektoren raten.

--------------------------------------------------
4. BUTTON PERSISTENT MACHEN
--------------------------------------------------

Der APH-Mobile-Menübutton muss unabhängig vom Sidebar-Zustand existieren.

Beispielprinzip:

const p = window.parent.document;

let btn = p.getElementById("aph-menu-btn");

if (!btn) {
    btn = p.createElement("button");
    btn.id = "aph-menu-btn";
    p.body.appendChild(btn);
}

WICHTIG:
appendChild auf p.body oder einen anderen dauerhaft sichtbaren Root-Container.

NICHT:
sidebar.appendChild(...)

--------------------------------------------------
5. ÖFFNEN DER SIDEBAR
--------------------------------------------------

Beim Klick auf #aph-menu-btn:

1. aktuellen Streamlit-DOM erneut abfragen
2. echten Sidebar-Control suchen
3. Streamlit-eigenen Button auslösen

Primär:

[data-testid="stSidebarCollapseButton"] button

Fallback:

[data-testid="stSidebarHeader"] button

Weitere Fallbacks nur verwenden, wenn sie anhand des tatsächlichen
Streamlit-1.60.0-DOM sinnvoll sind.

Keine eigene Navigation bauen.

Keine eigenen Seitenwechsel implementieren.

--------------------------------------------------
6. SIDEBAR-ZUSTAND ERKENNEN
--------------------------------------------------

Prüfe, ob die Sidebar aktuell geöffnet oder geschlossen ist.

Wenn geöffnet:
→ APH-Öffnen-Button darf ausgeblendet werden, WENN der native Schließen-Pfeil
  zuverlässig sichtbar ist.

Wenn geschlossen:
→ #aph-menu-btn MUSS sichtbar sein.

Noch robuster wäre:

Der APH-Button bleibt grundsätzlich vorhanden und wird nur über
display/visibility gesteuert.

Er darf niemals aus dem DOM gelöscht werden.

--------------------------------------------------
7. MUTATIONOBSERVER
--------------------------------------------------

Da Streamlit React verwendet und DOM-Elemente nach Reruns neu erzeugen kann,
soll der Zustand robust beobachtet werden.

Wenn erforderlich, einen MutationObserver auf parent.document.body verwenden.

Dieser soll lediglich:

- prüfen, ob Sidebar geöffnet/geschlossen ist
- sicherstellen, dass #aph-menu-btn existiert
- Sichtbarkeit des Buttons aktualisieren

KEINE Navigation über MutationObserver durchführen.

Keine Endlosschleifen erzeugen.

Observer nur einmal registrieren.

Beispielsweise über ein eindeutiges Flag:

window.parent.__aphSidebarObserverInstalled
