Du bist ein erfahrener Python-, Streamlit- und SQLite-Entwickler sowie Experte für sportliche Leistungsdiagnostik im Fußball.

Ich habe eine bestehende Fußball-Athletik-App mit Python, Streamlit und SQLite.

Erweitere meine App um ein vollständiges System für standardisierte Trainerbeobachtungen bei jedem einzelnen Test.

## Hauptziel

Bei jeder einzelnen Testübung soll der Trainer typische Beobachtungen einfach per Checkbox auswählen können.

Zusätzlich soll es ein Freitextfeld für weitere Beobachtungen geben.

Aus den ausgewählten Beobachtungen soll die App automatisch einen gut lesbaren und professionellen Beobachtungstext erstellen.

Beispiel:

Ausgewählte Beobachtungen:

* Knie fallen nach innen
* Fersen heben vom Boden ab
* Oberkörper kippt deutlich nach vorne

Automatisch erzeugter Text:

„Während des Deep Squats fiel auf, dass die Knie wiederholt nach innen auswichen, die Fersen den Bodenkontakt verloren und der Oberkörper deutlich nach vorne kippte.“

## Wichtige Grundregel

Die App darf keine medizinischen Diagnosen erstellen.

Verwende ausschließlich Formulierungen wie:

* Während des Tests fiel auf …
* Es war zu beobachten …
* Die Bewegung wirkte …
* Der Spieler zeigte …
* Die Ausführung erfolgte …
* Es zeigte sich ein Seitenunterschied …
* Die Bewegung konnte nicht durchgehend kontrolliert werden.

Nicht verwenden:

* Diagnose
* Verletzung erkannt
* krankhaft
* Therapie erforderlich
* Spieler ist verletzt
* Verletzungsrisiko
* medizinische Einschränkung
* Behandlung notwendig
* Sporttauglichkeit
* Spieler ist gesund
* Freigabe zum Sport

Bei Beschwerden darf nur stehen:

„Der Spieler gab während des Tests Beschwerden an. Der Test wurde abgebrochen beziehungsweise nicht weiter bewertet. Bei anhaltenden Beschwerden sollte eine medizinische oder therapeutische Fachperson hinzugezogen werden.“

## Zentrale Beobachtungsdatei

Lege alle Beobachtungen zentral ab.

Verteile die Texte nicht doppelt auf viele Streamlit-Seiten.

Erstelle beispielsweise:

```text
data/test_observations.py
```

oder:

```text
config/test_observations.py
```

Passe den Pfad an die vorhandene Projektstruktur an.

Die zentrale Struktur soll ungefähr so aufgebaut sein:

```python
TEST_OBSERVATIONS = {
    "fms_deep_squat": {
        "name": "FMS Deep Squat",
        "categories": {
            "Fuß und Sprunggelenk": [
                {
                    "id": "heels_lift",
                    "label": "Fersen heben vom Boden ab.",
                    "report_text": "die Fersen den Bodenkontakt verloren",
                    "positive": False
                }
            ]
        }
    }
}
```

Jede Beobachtung benötigt:

* eindeutige ID
* sichtbare Bezeichnung
* Textbaustein für den Bericht
* Kategorie
* Kennzeichnung positiv, neutral oder auffällig
* optional Seite rechts, links oder beidseitig
* optional Intensität
* optional automatischen Trainingsschwerpunkt

## Beobachtungsarten

Die App soll drei Beobachtungsarten unterscheiden:

### Positive Beobachtung

Beispiele:

* Bewegung kontrolliert ausgeführt
* stabile Beinachse
* gleichmäßiger Bewegungsablauf
* sichere Landung
* aktiver Armeinsatz

### Neutrale Beobachtung

Beispiele:

* Test wurde nach Wiederholung abgeschlossen
* bevorzugte Wendeseite rechts
* bevorzugtes Absprungbein links
* gewählte Startposition

### Auffällige sportliche Beobachtung

Beispiele:

* Knie weichen nach innen aus
* Gleichgewicht geht verloren
* Rumpf rotiert
* Beine schwingen nach außen
* deutlicher Seitenunterschied

Verwende nicht das Wort „pathologisch“.

## Bedienung in der App

Auf jeder Testseite soll ein Bereich vorhanden sein:

```text

```

Dieser Bereich soll standardmäßig eingeklappt sein, zum Beispiel mit:

```python
st.expander("Trainerbeobachtungen")
```

Innerhalb des Bereichs sollen die Beobachtungen übersichtlich nach Kategorien dargestellt werden.

Beispiel:

## Standardmodus und Expertenmodus

Erstelle zwei Ansichten.

### Standardmodus

Zeigt nur die 5 bis 10 häufigsten und wichtigsten Beobachtungen des jeweiligen Tests.

### Expertenmodus

Zeigt alle hinterlegten Beobachtungen nach Kategorien.

Verwende beispielsweise:

```python
mode = st.radio(
    "Umfang der Beobachtungen",
    ["Standard", "Experte"],
    horizontal=True
)
```

Die Auswahl soll die normalen Testeingaben nicht beeinflussen.

## Ausprägung

Für auffällige Beobachtungen soll optional eine Ausprägung gewählt werden können:

* leicht
* mittel
* deutlich

Die Ausprägung darf nur sichtbar werden, wenn die Beobachtung ausgewählt wurde.

Beispiel:

```text
☑ Knie fallen nach innen.

Ausprägung:
○ leicht
○ mittel
○ deutlich
```

Die Ausprägung soll im Bericht berücksichtigt werden:

* leichtes Nach-innen-Ausweichen
* mittleres Nach-innen-Ausweichen
* deutliches Nach-innen-Ausweichen

Die Auswahl der Ausprägung soll optional bleiben.

## Seitenangabe

Bei seitenspezifischen Beobachtungen soll auswählbar sein:

* rechts
* links
* beidseitig
* keine Seite

Beispiel:

```text
☑ Standbein wirkt instabil.

Seite:
○ rechts
○ links
○ beidseitig
```

Bericht:

„Während des Tests wirkte das linke Standbein zeitweise instabil.“

## Automatische Textgenerierung

Erstelle eine zentrale Funktion:

```python
generate_observation_text(
    test_id,
    selected_observations,
    custom_text=None
)
```

Die Funktion soll aus den ausgewählten Beobachtungen einen flüssigen deutschen Text erstellen.

Sie soll keine einfache Aufzählung mit Kommas erzeugen, sondern vollständige Sätze.

Beispiel mit einer Beobachtung:

„Während des 10-Meter-Sprints fiel auf, dass sich der Oberkörper bereits in der frühen Beschleunigungsphase deutlich aufrichtete.“

Beispiel mit zwei Beobachtungen:

„Während des 10-Meter-Sprints fiel auf, dass sich der Oberkörper früh aufrichtete und die Arme nur wenig aktiv mitarbeiteten.“

Beispiel mit mehreren Beobachtungen:

„Während des 10-Meter-Sprints fiel auf, dass sich der Oberkörper früh aufrichtete, die Arme nur wenig aktiv mitarbeiteten und beide Beine in der Schwungphase wiederholt nach außen geführt wurden.“

Positive Beobachtungen sollen gesondert formuliert werden:

„Positiv fiel auf, dass der Start reaktiv erfolgte und die Beschleunigung kontrolliert aufgebaut wurde.“

Wenn positive und auffällige Beobachtungen ausgewählt wurden:

„Positiv fiel der reaktive Start auf. Im weiteren Verlauf war jedoch zu beobachten, dass sich der Oberkörper früh aufrichtete und die Arme nur wenig aktiv mitarbeiteten.“

Verwende abwechslungsreiche Satzanfänge:

* Während des Tests fiel auf …
* Es war zu beobachten …
* Bei der Ausführung zeigte sich …
* Positiv fiel auf …
* Im Seitenvergleich zeigte sich …
* Während der Landung war zu erkennen …
* In der Beschleunigungsphase fiel auf …
* Beim Richtungswechsel zeigte sich …

Vermeide immer denselben Satzanfang.

## Keine widersprüchlichen Beobachtungen

Verhindere möglichst widersprüchliche Auswahl.

Beispiele:

Nicht gleichzeitig auswählbar:

* „Landung erfolgt instabil.“
* „Landung erfolgt stabil und kontrolliert.“

Oder:

* „Knie fallen nach innen.“
* „Beinachse bleibt durchgehend stabil.“

Falls beide dennoch ausgewählt werden, zeige eine verständliche Warnung:

„Bitte prüfe die Auswahl. Die Beobachtungen zur Beinachse widersprechen sich.“

Hinterlege dafür optional:

```python
"conflicts_with": ["stable_leg_axis"]
```

## Beobachtungen zurücksetzen

Ergänze einen Button:

```text
Beobachtungen zurücksetzen
```

Dieser Button darf nur die Beobachtungen des aktuell geöffneten Tests löschen.

* Seite anzeigen
* Freitext laden
* generierten Text anzeigen
* Änderungen ermöglichen

## Wiederverwendbare UI-Komponente

Erstelle eine zentrale Funktion, zum Beispiel:

```python
render_observation_selector(
    test_id: str,
    player_id: int,
    test_result_id: int | None = None,
    mode: str = "standard"
)
```

Rückgabe:

```python
{
    "selected_observations": [],
    "custom_text": "",
    "generated_text": "",
    "has_complaints": False
}
```

Die Testseiten sollen nicht jeweils eigenen doppelten Beobachtungscode enthalten.

## Fehlerbehandlung

Die App darf nicht abstürzen, wenn:

* zu einer Test-ID keine Beobachtungen vorhanden sind
* eine alte Beobachtungs-ID nicht mehr existiert
* ein Datenbankfeld leer ist
* kein Freitext eingegeben wurde
* keine Checkbox ausgewählt wurde
* ein Test noch keine Ergebnis-ID besitzt
* eine Datenbankmigration noch nicht durchgeführt wurde

Zeige dann verständliche Hinweise.

Beispiel:

„Für diesen Test sind derzeit noch keine standardisierten Beobachtungen hinterlegt.“
