KORREKTUR SCHRITT 7 – MOBILE BOTTOM NAVIGATION WIEDERHERSTELLEN UND FALSCHE ÜBERSETZUNGEN BEHEBEN

Aktueller realer Zustand nach der letzten Korrektur:

PROBLEM 1:
Die Mobile Bottom Navigation ist auf dem Smartphone jetzt komplett verschwunden.

PROBLEM 2:
Im Smartphone-Modus werden eigene Funktionsnamen und Texte teilweise automatisch von Englisch auf Deutsch übersetzt.

PROBLEM 3:
Beim Logout / Abmelden steht im Smartphone-Modus:

"sündigen"

statt:

"Abmelden"

Das darf nicht passieren.

WICHTIG:

* Keine Authentifizierungslogik neu schreiben.
* Keine Sessiondatenbank ändern.
* Keine Login-/Logout-Backendlogik ändern.
* Keine Desktop-Navigation beschädigen.
* Keine Pakete, Preise, Trainingslogik oder Diagnostik ändern.
* Keine Datenbankänderungen durchführen, sofern für diese UI-Korrektur nicht zwingend notwendig.

==================================================

1. MOBILE BOTTOM NAVIGATION MUSS WIEDER SICHTBAR SEIN
   ==================================================

Auf Smartphone bis einschließlich 768 px muss die Bottom Navigation wieder dauerhaft sichtbar sein.

Hauptpunkte:

* Start
* Spieler
* Tests
* Training
* Mehr

Beispiel:

🏠        👤        🧪        📅        ⋯
Start     Spieler   Tests     Training  Mehr

Anforderungen:

* position: fixed
* bottom: 0
* volle Viewport-Breite
* hoher z-index
* nicht hinter anderen Streamlit-Komponenten verschwinden
* ausreichende Touch-Flächen
* aktiver Menüpunkt sichtbar
* bestehendes Dark Design
* Inhalt unten mit ausreichendem Padding versehen

==================================================
2. WARUM IST DIE NAVIGATION VERSCHWUNDEN?
=========================================

Analysiere zuerst:

* wurde das HTML/CSS der Bottom Navigation entfernt?
* wurde die Render-Funktion nicht mehr aufgerufen?
* verhindert eine neue if-Bedingung die Mobile-Ausgabe?
* stimmt der Media Query noch?
* wird display:none gesetzt?
* liegt die Navigation hinter einem anderen Element?
* wurde die Navigation zusammen mit den alten <a href>-Links komplett entfernt?
* wird CSS nur auf Desktop geladen?

Den konkreten Grund finden und beheben.

==================================================
3. INTERNE NAVIGATION BEIBEHALTEN
=================================

Die Bottom Navigation soll NICHT wieder auf die problematischen normalen:

<a href="?nav=...">

Links zurückgestellt werden, wenn diese einen vollständigen Browser-Reload erzeugen.

Die sichtbare Bottom Navigation soll intern die funktionierende Streamlit-Navigation verwenden.

Bevorzugt dieselbe Routingfunktion wie Desktop.

Zum Beispiel konzeptionell:

navigate_to("start")
navigate_to("spieler")
navigate_to("diagnostik")
navigate_to("training")
navigate_to("mehr")

Die genaue bestehende Routingstruktur zuerst prüfen und wiederverwenden.

==================================================
4. MOBILE UI DARF NICHT AUTOMATISCH ÜBERSETZEN
==============================================

Aktuell werden im Smartphone-Modus eigene Begriffe teilweise automatisch übersetzt.

Das muss gestoppt werden.

Prüfe insbesondere:

* Mobile Bottom Navigation
* Mobile "Mehr"-Menü
* JavaScript-Komponenten
* i18n.py
* automatische Übersetzungsfunktionen
* CSS/HTML-Komponenten
* Browser-/Component-Translation
* Funktionsnamen aus Datenbank oder Navigation

Verbindliche Regel:

Nur feste UI-Texte dürfen über die bestehende kontrollierte i18n-Struktur übersetzt werden.

Eigene dynamische Inhalte und technische Bezeichnungen dürfen niemals automatisch durch freie Wortübersetzung laufen.

==================================================
5. EIGENNAMEN UND DYNAMISCHE DATEN NICHT ÜBERSETZEN
===================================================

Folgende Werte müssen grundsätzlich 1:1 angezeigt werden:

* Spielername

* Vereinsname
* Benutzername
* Paketname
* Übungsname, sofern als eigener Datenbankwert gespeichert
* vom Benutzer eingegebene Texte
* Trainer-Notizen
* Kundendaten
* technische Modulnamen, sofern explizit festgelegt

Beispiele:

Lion
→ Lion

NICHT:
Löwe

==================================================
6. UI-TEXTE NUR ÜBER FESTE SCHLÜSSEL ÜBERSETZEN
===============================================

Falls i18n.py verwendet wird:

Nur kontrollierte Keys verwenden.

Beispiel:

t("nav_logout")
→ "Abmelden"

Nicht:

t(variable_text)

wenn variable_text dynamisch aus Datenbank oder Code kommt.

Keine generische Wort-für-Wort-Übersetzung dynamischer Inhalte.
