KRITISCHE DIFFERENZANALYSE – SELBSTREGISTRIERTER TRAINER SPRINGT BEI FORMULAREINGABEN AUF START, ADMIN-ANGELEGTER TRAINER NICHT

Aktueller realer Produktionsbefund:

A) Trainerkonto wird vom Superadmin angelegt:
- Login funktioniert
- Spieler → Neu anlegen funktioniert
- Vorname, Nachname, Geburtsdatum usw. können normal eingegeben werden
- kein Sprung auf Startseite

B) Trainer registriert sich selbst über aphsystem.de:
- Registrierung funktioniert
- E-Mail-Verifikation funktioniert
- Login funktioniert
- Spieler → Neu anlegen öffnet sich
- erste Eingabe funktioniert
- bei der zweiten Eingabe, z.B. Vorname → Nachname, springt die App wieder auf Startseite
- danach muss Spieler → Neu anlegen erneut geöffnet werden

Vermutung:
Dasselbe Problem kann auch bei selbstregistrierten Vereinskunden bestehen.

WICHTIG:
Das Problem ist damit NICHT generell Mobile.
Es ist account-/session-/tenant-spezifisch.

NICHT erneut allgemeines CSS, Screen-Width oder Bottom-Navigation umbauen.

NICHT verändern:
- SMTP
- Docker
- .env
- requirements.txt
- config.py
- Kundenlöschung
- Trainingslogik
- Diagnostiklogik
- Preise/Pakete

relevanten Routing-/Auth-State protokollieren.

Nach erster Eingabe:
erneut protokollieren.

Nach zweiter Eingabe:
erneut protokollieren.

Insbesondere:

- nav_section
- _nav_goto
- user
- rolle
- verein_id
- trainer_id
- aktuelle Hauptseite

4. FALLBACK-LOGIK PRÜFEN
==================================================

Suche nach Logik wie:

if not trainer_id:
    goto start

if not verein_id:
    goto start

if not tenant:
    nav_section = Start

if role/status invalid:
    Startseite

oder:

wenn Account unvollständig
→ Defaultseite Start

Prüfe alle Account-spezifischen Guards.

==================================================
6. BESONDERS TRAINER-ZUORDNUNG PRÜFEN
==================================================

Da `spieler` real über `trainer_id` bzw. `verein_id` angebunden ist:

prüfe, ob selbstregistrierte Trainer tatsächlich eine gültige trainer_id / Trainer-Zuordnung erhalten.

Wenn Superadmin-Trainer eine solche Zuordnung hat, Selbstregistrierter aber nicht:
das könnte den Fehler erklären.

Nicht raten.
Direkt DB vergleichen.

==================================================
7. SPIELER-ANLEGEN CODE PRÜFEN
==================================================

Finde den Code für:

Spieler → Neu anlegen

Prüfe, ob während eines Widget-Reruns erneut ermittelt wird:

- aktueller Trainer
- aktueller Verein
- Mandant
- Rolle

und bei fehlendem Wert auf Start zurückgefallen wird.

==================================================
8. KEINE NAVIGATION BEI UNVOLLSTÄNDIGEM ACCOUNT
==================================================

Falls ein Pflichtwert fehlt:

nicht einfach auf Startseite springen.

Stattdessen:
klarer Fehler / Hinweis.

Aber primär die Selbstregistrierung so korrigieren, dass die gleichen gültigen Account-/Mandantenstrukturen erzeugt werden wie bei einem funktionierenden Trainerkonto.

12. ROOT CAUSE BEHEBEN, NICHT SYMPTOM
==================================================

Wenn die Ursache ein fehlender Trainer-/Mandanten-Datensatz ist:
Registrierungslogik korrigieren.

Wenn Ursache im Login-User-Dict liegt:
zentrale Session-Aufbereitung korrigieren.

Wenn Ursache ein account-spezifischer Guard ist:
diesen korrekt machen.

Nicht einfach Spieler-Seite mit zusätzlichem nav_section-Fix patchen.
