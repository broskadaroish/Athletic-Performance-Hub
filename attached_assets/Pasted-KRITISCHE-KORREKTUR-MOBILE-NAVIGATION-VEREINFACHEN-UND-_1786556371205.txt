KRITISCHE KORREKTUR – MOBILE NAVIGATION VEREINFACHEN UND ALLE 0–20 TRIGGER-BUTTONS ENTFERNEN

Der Fehler besteht im realen Test weiterhin.

Nach Login erscheint weiterhin teilweise:

"Your Football Athletik App artifact encountered an error"

Zusätzlich wurden bzw. werden auf Seiten interne Buttons 0–20 mit ⬡-Symbolen sichtbar.

Aus dem bisherigen Diagnosebericht ist klar:

Diese 0–20 Elemente stammen aus internen Trigger-Buttons, die für die Mobile-Navigation verwendet werden.

Die bisherige Lösung:

CSS :has(button[aria-label^="⬡"])

zum Verstecken dieser Buttons ist NICHT akzeptabel und funktioniert im realen Browser nicht zuverlässig.

VERBINDLICHE NEUE REGEL:

DIESE TRIGGER-BUTTON-ARCHITEKTUR KOMPLETT ENTFERNEN.

==================================================

1. KEINE VERSTECKTEN 0–20 BUTTONS MEHR
   ==================================================

Entferne vollständig alle Navigations-Hilfsbuttons wie:

⬡0
⬡1
⬡2
...
⬡20

bzw. entsprechende:

st.button(...)
range(...)
Trigger-Button-Schleifen
Hidden-Button-Bridges

Sie dürfen:

* nicht gerendert werden
* nicht per CSS versteckt werden
* nicht im DOM existieren
* nicht für Navigation benötigt werden

Keine Lösung mehr über:

:has(button[aria-label...])

verwenden.

==================================================
2. KEINE HTML-/JAVASCRIPT-BRIDGE
================================

Für die Mobile Bottom Navigation nicht mehr verwenden:

* versteckte st.button-Trigger
* img-onload
* img-onerror
* künstliche DOM-Events
* JavaScript-click auf versteckte Buttons
* query-param href Navigation
* CSS-Tricks zum Verstecken technischer Steuerelemente

Die Navigation soll möglichst vollständig mit nativen Streamlit-Funktionen umgesetzt werden.

==================================================
3. MOBILE NAVIGATION MIT NATIVER STREAMLIT-KOMPONENTE
=====================================================

Baue die Mobile Bottom Navigation mit EINER nativen Streamlit-Auswahlkomponente.

Bevorzugte Reihenfolge:

1. st.segmented_control, falls in der aktuell verwendeten Streamlit-Version stabil verfügbar

oder alternativ:

2. st.radio(horizontal=True)

Die Navigation soll fünf sichtbare Optionen besitzen:

🏠 Start
👤 Spieler
🧪 Tests
📅 Training
⋯ Mehr

Technisch nur EINE Widget-Komponente.

Keine 21 versteckten Widgets.

==================================================
4. INTERNES ROUTING
===================

Die Auswahl soll die bereits bestehende interne Routinglogik verwenden.

Beispielprinzip:

mobile_nav = st.segmented_control(
...,
options=["Start", "Spieler", "Tests", "Training", "Mehr"]
)

Bei Änderung:

route = entsprechende bestehende Route

Dann:

st.session_state["current_page"] = route

und falls erforderlich:

st.rerun()

Keine vollständige Browsernavigation.

Kein:

<a href="?nav=...">

==================================================
5. DESKTOP-ROUTER WIEDERVERWENDEN
=================================

Prüfe, welche zentrale Routingfunktion Desktop bereits verwendet.

Mobile Navigation soll genau dieselbe Route-/Page-Definition verwenden.

Wenn möglich eine zentrale Funktion:

navigate_to(route)

verwenden.

Beispiel:

navigate_to("start")
navigate_to("spieler")
navigate_to("diagnostik")
navigate_to("training")
navigate_to("mehr")

Desktop und Mobile dürfen nicht zwei unterschiedliche Routingsysteme besitzen.

ABER:

CSS nur für das Layout und Styling verwenden.

Nicht für das Verstecken technischer Triggerbuttons.
