MASTER-AUFTRAG – APH MOBILE SESSION + SLIDE-NAVIGATION STABILISIEREN

WICHTIG:
Noch nicht blind umbauen.
Zuerst die bestehende Session-, Cookie-, Login- und Mobile-Navigation vollständig analysieren.
Danach nur die tatsächlich gefundenen Ursachen korrigieren.

==================================================
TEIL A – MOBILE LOGIN / SESSION-PERSISTENZ
==================================================

AKTUELLES FEHLVERHALTEN:

Auf dem Smartphone bin ich in APH eingeloggt.

Wenn ich:
- das Handy-Display kurz ausschalte,
- den Browser kurz in den Hintergrund schicke,
- zu einer anderen App wechsle
- und anschließend zu APH zurückkehre,

muss ich mich teilweise erneut anmelden.

Das darf bei einer gültigen Login-Session NICHT passieren.

ZIEL:

Ein Benutzer soll angemeldet bleiben, solange seine serverseitige
APH-Session gültig ist.

Ein kurzer:
- Display-Lock
- Browser-Wechsel
- App-Wechsel
- Tab-Wechsel
- Streamlit-Reconnect
- Netzwerkunterbruch

darf nicht automatisch zum Logout führen.

--------------------------------------------------

NICHT einfach Timeout-Werte erhöhen, wenn das Problem in der
Session-Wiederherstellung liegt.

--------------------------------------------------
A2 – SESSION MUSS SERVERSEITIG WIEDERHERSTELLBAR SEIN
--------------------------------------------------

Wenn Streamlit seinen st.session_state verliert oder eine neue
WebSocket-/Streamlit-Session erstellt:

1. ath_sid Cookie lesen
2. Session-ID serverseitig validieren
3. Benutzer aus der Session laden
4. Benutzerstatus prüfen
5. st.session_state wiederherstellen
6. Benutzer bleibt eingeloggt

Ein leerer neuer st.session_state allein darf NICHT bedeuten:
→ Benutzer ausloggen.

--------------------------------------------------
A3 – COOKIE PRÜFEN
--------------------------------------------------

Prüfe insbesondere:

- Ablaufzeit / Max-Age
- Path=/
- Secure bei HTTPS
- SameSite
- Domain
- Cookie wird nicht unnötig überschrieben
- Cookie wird bei normalem Rerun nicht gelöscht
- Cookie wird bei Streamlit-Reconnect wieder gelesen

Produktiv läuft APH über:

https://aphsystem.de

Cookie muss dort zuverlässig funktionieren.

--------------------------------------------------
A4 – SICHERHEIT NICHT ABSCHWÄCHEN
--------------------------------------------------

Folgende Fälle müssen weiterhin ausloggen bzw. Zugriff verhindern:

- Benutzer klickt Logout
- Session serverseitig abgelaufen
- Konto deaktiviert
- Passwort geändert und bestehende Sessions sollen invalidiert werden
- Session-ID ungültig/manipuliert

KEIN permanenter unsicherer Login.

Bestehenden Brute-Force-Schutz nicht verändern.

TEIL B – SLIDE-NAVIGATION MOBILE STABILISIEREN
==================================================

AKTUELLES FEHLVERHALTEN:

Das mobile Slide-Menü hängt gelegentlich.

Beispiele:

- Menü reagiert nicht
- Menü öffnet/schließt nicht sauber
- Navigation reagiert erst nach erneutem Klick
- nach Browser-/App-Wechsel kann das Menü hängen
- nach Streamlit-Rerun kann der Zustand inkonsistent sein

ZIEL:

Slide-Navigation muss auf Android/iPhone und Desktop zuverlässig
funktionieren.

--------------------------------------------------
B1 – URSACHE ANALYSIEREN
--------------------------------------------------

Prüfe:

- mobile.py
- app.py
- Slide-Navigation
- JavaScript
- CSS
- Streamlit Components / HTML
- session_state Navigation
- _nav_goto
- nav_section
- Subnavigation
- rerun
- Event Listener
- DOM IDs
- doppelte Listener
- Overlay / z-index
- pointer-events
- Menü-Zustand nach rerun

--------------------------------------------------
B2 – KEINE DOPPELTEN EVENT LISTENER
--------------------------------------------------

Prüfen, ob durch Streamlit-Reruns JavaScript-Listener mehrfach
registriert werden.

Falls ja:
→ idempotente Initialisierung einbauen.

Ein Rerun darf nicht immer weitere click/touch Listener hinzufügen.

--------------------------------------------------
B3 – MENÜZUSTAND
--------------------------------------------------

Der Zustand muss eindeutig sein:

OPEN
oder
CLOSED

Nach Navigation:
→ Menü automatisch schließen.

Nach Rerun:
→ definierter Zustand.

Nach Browser-Resume:
→ Menü weiterhin bedienbar.

Kein unsichtbares Overlay darf die Seite blockieren.

--------------------------------------------------
B4 – TOUCH / MOBILE
--------------------------------------------------

Prüfen:

- touchstart/click Konflikte
- doppelte Auslösung
- pointer-events
- Overlay
- Scroll-Lock
- body overflow
- z-index
- Hamburger-Button

Nach Schließen des Menüs muss die normale Seite wieder vollständig
scroll- und anklickbar sein.
